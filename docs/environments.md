# Isolated project environments

`EnvironmentManager` stores allocations in its own SQLite WAL database under an explicit workspace root. Register opaque bot IDs with their fixed Telegram network; pass an exact registered-project resolver from the shared queue. `allocate` reserves a unique bot, local port, branch, worktree path, data directory and application DB. IDs/branches are unique case-insensitively to prevent Windows filesystem aliases; reserved Windows device names are rejected. Repeated allocation of the same environment is idempotent; a second branch cannot share these resources. A multiplayer scenario uses one environment with several actor IDs. There is no game-specific code.

`createWorktree` emits `git worktree add -b <branch> <owned-path> HEAD` through an injected executable/argv runner. Creation has a persisted exclusive job lock. It never merges, pushes, deploys or removes a worktree. The caller executes this command only in an authorized project repository. Existing directories and all symlink/junction components (including dangling or internal aliases) are rejected. The workspace's canonical root must not change. Bot tokens are deliberately absent from the environment schema; local adapters resolve opaque bot IDs separately.

`start` uses an injected `ProcessFactory`, supplies the isolated port/data/database paths, and waits for a localhost HTTP readiness URL on the allocated port. Process ownership is claimed with a SQLite compare-and-set; only the owning manager can stop a live process. Start failure stops its exact child handle and persists a redacted error. If cleanup cannot stop the child, ownership is retained and another start is rejected until an explicit stop succeeds. Unexpected exit of a local child marks the environment failed. Allocations are retained after stop so restart does not silently change a bot or database. A manager reopened after a crash conservatively reports `EXTERNAL_PROCESS_OWNER` for a previously ready/starting or still-owned failed environment; external process recovery requires explicit reconciliation. It does not kill stored PIDs or arbitrary host processes.

`localProcessFactory` spawns only explicitly allowlisted absolute executable paths with argv, `shell:false`, and hidden Windows windows. Children receive a small OS environment plus their isolated port/data/database paths, without inheriting model API credentials. Existing listeners on the allocated IPv4 port are rejected before spawn. Local readiness has a deadline, cancels response bodies, and rejects foreign URLs and redirects. Port probing has an unavoidable OS-level close/bind race; readiness is not cryptographic proof of server identity. Stop targets only the spawned child handle, with bounded graceful termination and forced termination of that same child. This adapter supervises a direct server process, not arbitrary descendant trees; use a dedicated process-tree supervisor if a project spawns grandchildren. `gitWorktreeRunner` validates worktree-add arguments, strips unrelated environment variables and has a 60-second child deadline. These are for trusted local project manifests, not commands received from an untrusted webpage.

The tests include four independent SQLite allocator processes (41 unique allocations and a single winner for a shared bot), lifecycle/failed-stop ownership, worktree creation exclusion, dangling/internal junction rejection, and actual local Node children for readiness/stop, timeout, occupied-port refusal, runtime exit and credential-environment isolation. Bot provisioning, attaching browser actors and GameTycone integration are not yet wired into the UI. These checks are not live Telegram acceptance. A stopped environment retains its resources; explicit resource release and crash/job reconciliation remain operator tasks. Custom injected adapters are responsible for bounded readiness and reliable stop just as the local adapter is.
