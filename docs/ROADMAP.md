# Viewer 2 — план создания продукта

Обновлено: 11.11.2026. Ветка: `viewer2-platform`. Статус кода — см. [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

## Что мы строим

Инструмент, в котором **Codex / Claude ставят задания, Antigravity (Gemini Flash) их выполняет, а настоящий Telegram Web под управлением Playwright проверяет результат** — чаты с ботами, группы, Mini Apps, Widgets. Работает локально, секреты не попадают к моделям, независимые ветки не мешают друг другу.

## Конечная точка: когда продукт считается завершённым

Продукт готов, когда выполнены **все** условия (проверяются, а не декларируются):

| # | Критерий приёмки | Как проверяем |
|---|---|---|
| D1 | Координатор ставит задание → живая беседа Antigravity выполняет → координатор принимает или возвращает на исправление | Сквозной прогон на реальной беседе, 3 задания подряд без ручных действий, кроме запуска `/agents` |
| D2 | Три исполнителя работают параллельно в отдельных worktree без пересечений, фактическая модель подтверждена | Тест с тремя задачами; журнал модели |
| D3 | Пилотный Telegram-проект (GameTycone + маленький независимый) проходит автотест: `/start` → кнопка → Mini App → действие → ответ бота | Сценарии в реальном Telegram WebK на аккаунтах тестовой сети |
| D4 | Групповой сценарий с двумя акторами и проверка Widgets (в тестовой сети) | Сценарий + скриншоты реальных пикселей |
| D5 | Ошибка, найденная тестом, исправляется через цикл «задание → правка → повторный тест» без участия человека | Один задокументированный пример |
| D6 | Изоляция: правки, базы, порты и боты разных веток не пересекаются; отмена и сбой освобождают ресурсы | Тесты concurrency + ручной прогон двух веток |
| D7 | Секреты (токены, cookies, `initData`) не видны моделям и не попадают в отчёты | Тесты редактирования + аудит экспорта |
| D8 | Живой Dev Bot переведён на новую очередь, старый можно выключить | Cutover по чек-листу с откатом |
| D9 | `npm test`, `tsc`, `eslint`, `next build` зелёные в CI на каждый push | GitHub Actions |
| D10 | Запуск «с нуля» за ≤15 минут по README на чистой машине | Прогон по инструкции |

## Правила работы

- Объёмную и механическую работу — Antigravity через очередь; координатор формулирует критерии и выносит вердикт, а не переписывает сам.
- Любой этап считается закрытым только после независимой проверки (`npm test`, `tsc`, `eslint`, `next build`).
- Не трогать: оригинал на рабочем столе, действующий Dev Bot и чужие worktree без явного согласия.
- Секреты не печатать и не коммитить; реальные аккаунты и платежи — только по решению пользователя.
