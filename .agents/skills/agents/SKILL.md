# /agents — исполнитель очереди заданий Viewer

Когда пользователь вызывает `/agents <projectId>` (или говорит «жди задания от Codex/Claude»),
эта беседа становится **исполнителем**: координатор (Codex или Claude) ставит задания в очередь,
ты их выполняешь и сдаёшь отчёт. Пока заданий нет — токены не тратятся.

Все команды выполняются из каталога Viewer Antigravity.

## 1. Взвести ожидатель

```bash
npm run --silent agents:wait -- --project=<projectId>
```

- `--project` обязателен. Если проект не зарегистрирован, команда завершится с ошибкой и списком
  известных проектов. **Не подставляй другой проект** — сообщи пользователю.
- Команда блокируется, пока не появится задание. Ничего не опрашивай в цикле сам.
- Когда задание появится, в stdout придёт **одна строка JSON** со `status: "NEW_TASK"`,
  полями `owner`, `task` и `instructions` (готовые команды для этого задания).
- `status: "IDLE_TIMEOUT"` — заданий не было; просто взведи ожидатель снова.

## 2. Выполнить задание

Из `task` важны:

| Поле | Что делать |
|---|---|
| `goal`, `acceptance` | Цель и проверяемые условия готовности |
| `workdir` / путь проекта, `branch` | Где работать. Параллельные изменения — только в отдельном worktree |
| `allowedPaths` | Менять файлы только в этих областях |
| `constraints` | Жёсткие ограничения |
| `checks` | Команды, которые нужно **запустить программно** и приложить результат |
| `round > 0` | Это возврат на исправление: прочитай последний `verdicts[].notes` и прошлый `report` |

Правила:

- Небольшую задачу выполняй сам. Независимые части большой задачи распределяй максимум между
  **тремя** субагентами, каждый в своём worktree.
- Примерно раз в 10 минут продлевай владение (команда из `instructions.heartbeat`).
  Если в ответе `cancelRequested: true` — немедленно остановись и выполни `instructions.ackCancel`.
- Ответ `LEASE_LOST` означает потерю права выполнять задание: прекрати работу и
  ничего не сдавай.
- Не делай merge в основную ветку и не запускай деплой — это решает координатор после вердикта.
- Никогда не помещай в отчёт токены ботов, `initData`, cookies и ключи API.

## 3. Сдать отчёт

Запиши отчёт в файл (например, `%TEMP%/report-<taskId>.json`):

```json
{
  "summary": "Что сделано и чем подтверждено — кратко",
  "revision": "<commit sha, если были изменения>",
  "changedFiles": ["path/one.ts"],
  "checks": [{ "command": "npm test", "ok": true, "details": "42 passed" }],
  "artifacts": [{ "type": "screenshot", "path": "C:/.../shot.png", "note": "экран магазина" }],
  "openQuestions": [],
  "model": "gemini-3.8-flash"
}
```

Затем выполни команду из `instructions.report`. Если задачу выполнить невозможно —
`instructions.fail` с причиной (при исчерпании квоты укажи `--code=QUOTA_EXHAUSTED`).

`checks[].ok` должен отражать **фактический** результат запуска. Успешный отчёт без выполненных
проверок координатор вернёт на доработку.

## 4. Снова взвести ожидатель

Сразу после сдачи отчёта повтори шаг 1. Вердикт координатора придёт как новое задание
(`round` + 1), если нужны исправления.
